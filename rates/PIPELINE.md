# 外貨・円建一時払利率の更新パイプライン

## 現状（自動監視と公開ブリッジは実装済み。公式数値の自動照合は未実装）

1. `rate-monitor.yml`：13商品の公式参照先を毎日確認。ページの取得・変更状況を記録する。**ページ更新と利率更新は別物**
2. `rates/catalog.json`：商品IDと参照URL
3. `rates/proposed.json`：候補データ。未確認の利率をそのまま公開しない
4. `rates/approved.json`：照合済み利率を入れるデータ領域。現在は空
5. `apply-approved-rates.yml`：承認済みの利率だけを有効期間中に比較アプリへ反映。毎日10:47 JSTにも実行。数値がない場合は何も変更しない
6. `apply_verified_rates.py`：現在の分割HTML内の「一時払」画面を更新し、旧期間の利率は履歴に残す。分割ファイル数が変わる場合は読み込みファイルも同時に更新

## approved.json の1件に必要な項目

- product_id: `catalog.json` 内のID
- currency: 通貨（USD/AUD/JPY等）
- condition_id: 安定した条件ID（識別用）
- label: 既存画面の利率種別名と完全一致
- term: 保証期間などの表示名と完全一致
- lo, hi: 年齢範囲。既存画面と一致
- rate_percent: 公式に確認済みの数値（百分率）
- payout: 男女別定期支払率のある商品では male/female の双方を指定
- valid_from, valid_to: 適用期間（ISO日付）
- verified_on: 公式原本の確認日
- verification: `approved` または `pending`
- official_url: 数値が確認できる公式ページ・PDFのURL
- source_label: 出典を識別できる説明

**注意:** `verification=approved` は人間または独立した検証プロセスの承認結果を表す必要がある。単にURLへアクセスできたというだけでは承認してはいけない。現段階のバリデータは構造の検査のみで、公式表の真偽を照合する機能ではない。

## 安全策

- 期間が始まる前には公開しない
- 期限切れの利率を新期間として再利用しない
- 既存の条件と一致しないものは公開を停止する
- 男女別支払率を旧期間から無断で引き継がない
- 利率データが空なら公開中のアプリに触れない
- 分割ファイルの読み込み設定が想定外の場合は処理を中断する

## 残っている作業

- 13商品の販売チャネル別公式URLの確認
- 各社のPDF/HTMLから期間・年齢・プラン・通貨別の利率を読み取るアダプター
- 公式原本のハッシュ/根拠欄と独立した検証手順
- 117版の公開本体への安全な移行（現行GitHubの分割ファイルとは別管理）
- GitHub Actionsの実行成功と画面表示の確認

この設計は、確認済み利率のHTML手動差替えを不要にするための土台であり、**まだ公式利率の完全自動更新ではありません。**
