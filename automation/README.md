# 半月ごとの利率更改 — 安全な自動化の基盤

このブランチは本番 `main` / `index.html` の利率や画面を変更しない。

## 現段階で自動化したこと
- GitHub Actions が毎日10:15 JSTに公式ページの到達性・変更を確認（1日・16日以外も再試行）
- 出典URL・検査日時・SHA-256・通信結果を `source-audit.json` に記録
- 非公式ドメインへのリダイレクトや過大応答を拒否
- 監査データを利率そのものとして利用・公開しない

## 本番無人公開に必要な残工程（未実装）
1. **各商品・各代理店の公式利率掲載先**を特定し、契約条件別の値を確実に読み取る専用パーサーを作成する。HTML変更やPDF取得不能を検知したら自動承認しない。
2. 通貨、契約年齢、運用年数、払込額帯、プラン、性別（該当商品）、対象適用期間のキーを固定し、前回同条件との差分を照合する。
3. 1日/16日適用期間の一致、全必須セル、数値範囲、出典、重複、バージョンを検証。確認不能な条件は **確認待ち** とし旧利率を現行に転用しない。
4. 第117版の一時払利率の表示ロジックを独立したデータファイルに移し、アプリ本体と分離する。現在の32分割ページを置換する前にPC/スマホで回帰テストする。
5. テストを通ったデータのみ原子的に `main` へ反映、GitHub Pages公開後の表示チェックを行う。不一致時は前回の正しい版に戻すか確認待ち表示を維持する。

**重要**: 公式ページが閲覧できることと、数値が正しく取得できたことは別。現段階は監視基盤であり「完全無人公開の完成」を意味しない。

## 情報保護・公開データ分離（必須）

**重要：このリポジトリの GitHub Pages / GitHub Actions Artifacts は、アクセス制御された社内保管場所の代わりにならない。**

- 現行 v117 には「募集人用資料」というカテゴリが埋め込まれている。非表示の `iframe`、`srcdoc`、base64 の画像・PDFも訪問者がソースから取得できるため、見た目の非表示では機密保護にならない。
- `automation/security_gate.py` は、内部カテゴリ・内部資料の目印・埋め込みファイルを検出し、現状の**アプリ全体の公開を拒否**する。自動検査に引っ掛からない場合でも、安全だと断定してはならない。公開承認済みファイルの個別ホワイトリストが必要。
- 従来の `insurance-rate-review-preview` ZIP の新規生成・アップロードを PR CI から停止した。**過去の既存成果物は自動削除できていない**ので、GitHub Actions の各成果物と保持期間を管理者が点検し、内部資料を含むものは削除する。
- `automation/public_rate_projection.py` は、54条件の取得済み利率から、会社名・商品名・通貨・プラン・年齢帯・適用期間・利率・男女別定期支払率など許可項目のみを抽出する。顧客情報、社内メモ、募集人資料、画像、PDF、代理店URLなどの不必要な項目はコピーしない。これも `publication_allowed: false` なので公開にはまだ使わない。
- **公開前の独立監査が必須**：個人情報、顧客契約・告知・相談記録、募集人専用資料、社内推奨一覧、手数料・代理店管理情報、代理店限定の引受情報、アクセスキー、内線・担当者連絡先、転載禁止物、画像内の文字を、HTML/JS/JSON/ZIP と過去版のファイルすべてで確認する。
- 社内向け資料を利用する場合は、**GitHub Pages から切り離し**、適切な認証・権限管理・監査ログを備えた社内ストレージに保管する。パスワード付きリンクや単なるタブ非表示だけでは不十分。
- 本番公開されている元ファイルや過去のコミットに機密情報があった場合は、画面を隠すだけでなく公開元ファイルを削除・差し替え、必要に応じて履歴・キャッシュ・共有URL等の対処を検討。機密・個人情報の漏えい可能性は社内の情報管理責任者に確認。
